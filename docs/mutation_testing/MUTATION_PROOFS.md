# Mutation testing, proof side: the four survivors and how they were closed

Source: `benchmarks/evidence/mutation_testing.json` of the first full run (seed 20261001, 16 proof-side mutants).
A proof-side mutant changes one definition in `types/*_generated.bend`; the facade proof file that reaches it
(`proofs/api/<Name>_<op>_ssz_proof_generated.bend`, statements locked) is re-checked and must FAIL. Four of the 16
still checked. This file is separate from the mutation sections of RESULTS.md and TRUST.md (owned by the harness
branch); the text here can be linked or merged from there.

| # | Mutant | Verdict | Closed by |
|---|---|---|---|
| 1 | `NextSyncCommitteeBranch_build`: read offset `0` to `1` | equivalent (dead code) | nothing to close |
| 2 | `BLSToExecutionChange_encode`: `O.out_at(5n)` to `O.out_at(6n)` | equivalent (capacity only) | nothing to close |
| 3 | `Cell` encode, `b2048_valid`: `2048` to `2049` | real gap | `Cell_serialize_over`, `Cell_serialize_in` |
| 4 | `SyncCommitteeContribution_bx_size`: `160` to `161` | real gap | `SyncCommitteeContribution_encoded_size` (boxed form) |

## 1. `NextSyncCommitteeBranch_build` is dead code

`X_build(buf, size) = P_read(buf, 0, size)` is emitted for every name (codegen/impl/typed_object_runtime.py) as part of the decoder
group, but nothing calls it: a search of the whole tree (types, src, proofs, e2e, benchmarks, tests, codegen) finds
only its own definition and the `types/runtime_index.json` entry. `X_decode` reads through `X_ok` and `X_read`
directly. A mutation of an uncalled definition cannot change any behavior, so no statement, test or program can
distinguish it: equivalent. (The same holds for every `X_build`.)

## 2. `O.out_at(5n)` is an initial capacity

`O.out_at(d)` is `Array.new(U32, d, 0)`: a zero array of 2^d words, the buffer the encoder writes into; the result
is `B.Buf{out, 76}` with the length given separately (`O.out_done(76, ...)`). The encoder needs 76 bytes = 19
words; 2^5 = 32 words is the least depth that holds them, and `6n` doubles the allocation to 64 words. The bytes
written and the length are the same, so no statement about the output (`encode_eval`, `encode_spec`, `encoded_size`,
`roundtrip`) and no conformance or fuzz test can see it; the output buffer's capacity is not part of the contract.
Equivalent as a behavior, a pure over-allocation. (Under-allocation, `4n`, is not equivalent: the writer would run
past the array; it is not a `const+1` mutant.) This is a systematic class: every `const+1` on an `out_at(..)`
argument is of this kind.

## 3. `b2048_valid`: the bounds of a byte vector's validity check

`Cell` is a 2048-byte vector; `b2048_valid(o) = O.words_ok(o, 2048, 2048, False{}, 1)` (lower bound, upper bound,
unbounded flag, unit). The locked statements about `Cell` reach the validator only through hypotheses
(`hv: (o, True{}) == b2048_valid(o)` in the end-to-end serializer bridge, which lives in `e2e/`, not in the encode
facade): they say what follows from validity, never that 2049 bytes are invalid. Raising the upper bound (or the
lower bound, which would make every 2048-byte vector invalid) therefore went unseen.

New statements, generated by `codegen/proofs/slop/reported_size_and_vector_bound.py` into `proofs/slop/size/size_and_bound_{fulu,generic}.bend`
and filed by object_api_coverage_gate as `serialize_valid` laws (so they land in the name's encode facade):

* `X_serialize_over()`: the checked serializer refuses `O.Words{ws, N+1}` (`== (o, O.refused())`), with `ws` a
  concrete zero storage with room for N+1 bytes (the validity check also reads the storage's size, so with room the
  bound is the only thing that refuses). Kills the upper-bound mutant.
* `X_serialize_in()`: the serializer of exactly N bytes equals `(fst(X_encode(w)), O.encoded(snd(X_encode(w))))`.
  Kills the lower-bound mutant (that mutant survived the first closure, `_over` alone).
  Stated up to 4096 bytes (computing Blob's 131072-byte encoding did not check in 600 s); for Blob the lower side
  stays with the e2e hypotheses.

Both are by computation (`{==}`), 6 s for the Fulu file. Names covered: every byte vector whose validity is
`words_ok(o, N, N, False{}, 1)`: Blob, Cell and the generic `vec_uint8_*` forms. Unit > 1 vectors (the branches,
`b32` vectors) are not covered: there, `N+1` is also refused by the unit check, so `hi+1` is equivalent for them
(every word-multiple above N would need a separate statement; not claimed).

## 4. `SyncCommitteeContribution_bx_size`: the reported size of a boxed object

`X_bx_size(o) = (o, 160)` is the size pass that containers use for a list of fixed-size elements (the sum over
elements). `X_encoded_size` (codec_N.bend) states the length of `X_encode(v)`, not what the size pass reports, so a
wrong constant there was invisible to the facade.

New statement, one per name whose size pass is a literal: `X_encoded_size(o: Boxed<X>, v: X)`
`: size(X_bx_size(o)) == size(X_encode(v))`, by computation (`{==}`). The same-named law of codec_N.bend is a
different file; object_api_coverage_gate files both under `encoded_size`. Names: SyncCommitteeContribution, SignedBeaconBlockHeader,
DepositData, SyncAggregate (Fulu) and the generic forms with a literal size pass.

## 5. Constants of the generated encoders and root wrappers (group `constant`, `hashtreeroot-constant`)

Second run: 112 `constant` and 45 `hashtreeroot-constant` proof-side survivors (6 of the 112 were already closed by section 3).
Why they survived: every locked statement of a name is written at position 0 of a value that the facade quantifies
over symbolically or checks through its encoding, so (a) the unaligned packing writers (`P_pw1..3`, `P_pwu`, the
`pos .&. 3` masks) are never reached, (b) the invalid-value marker of a checked writer (`2147483648`) and the
length constants of the serializer (`ser_done(.., N, ..)`, `out_done(N, ..)`) and its write position (`putk(.., 0, o)`)
are only visible through a refused result or a nonzero-position write, and (c) `X_hash_tree_root`'s literal hasher
length and segment feed a callee that, for a leaf, never reads them.

New generator `codegen/proofs/slop/encoder_constants.py` writes `proofs/slop/constants/<X>.bend` (one module per name, so a
facade checks only its own laws); object_api_coverage_gate files `<X>_mc_*` in the encode facade (`serialize_valid`), `<X>_mc_root` in the
root facade. Laws (all by `{==}`; the first three symbolic):

| law | statement | closes |
|---|---|---|
| `mc_poison_<P>` | `P_pk(out,pos,(o,False{})) == (out,(o,O.poison()))` | the `2147483648` marker of a checked writer |
| `mc_bxpoison_<S>` | `S_bx_putk(out,pos,O.BNone{}) == (out,(O.BNone{},O.poison()))` | the same in boxed writers |
| `mc_bxcount_<S>` | the count `S_bx_putn` reports for a missing element is 0 | `(.., 0)` of `_bx_putn` |
| `mc_put` | `P_put` at positions 0..3 of a nonzero value equals `O.put_words` of the value's aligned bytes (records: seed words) | shifts, carries, word indices, masks of `_pw*`, `_pwu`, `_put` |
| `mc_ser` | `X_serialize(w) == (fst(X_encode(w)), encoded(snd(X_encode(w))))` for a witness (seed, or default with one seeded field set, or packed words / bits with nonzero words) | `senc_out`/`enc_out` length constants, the position `0` of `senc_go`/`serialize` |
| `mc_root` | the wrapper of a `words_root`/`bits_root` name is its root function at `64n`, segment `0` | the segment of the Merkle-branch roots |

`mc_ser` is not generated when the default object would encode to more than 8192 bytes (BeaconState: its law took
over 430 s), nor for names that already have `serialize_in`.

### Equivalent (no statement can tell them apart; the checker compares by conversion and the changed literal disappears)

## 6. Round 2: write start, serializer depth, length constants, reported sizes, read offsets (small groups)

Generator `codegen/proofs/slop/write_start_and_sizes.py` writes `proofs/slop/size/<X>.bend` (object_api_coverage_gate files `<X>_ms_*`
in the encode facade; `_ms_dec` / `_ms_build` in the decode facade). The mutations of `capacity-1` (an under-allocated

not caught because the earlier witnesses were all-zero or too large to compute (Blob, HistoricalBatch, SyncCommittee,
vec_uint256_512). The new laws are symbolic wherever the object is large:

| law | statement | closes |
|---|---|---|
| `ms_serdepth` | `X_serialize(o) == X_senc_(out/put)(P_putk(O.out_at(Kn), 0, o))`, symbolic in o; K is the least depth for the schema size (the generator stops if the generated file disagrees; variable names use the schema's greatest size) | write start 0, depth K-1 (and K+1) |
| `ms_senc_out` / `ms_encout` | `X_senc_out((out,(o,0))) == (o, encoded(Buf{out,N}))`, `X_enc_out((out,o)) == (o, Buf{out,N})`, symbolic | the reported length N |

Re-run, 27 survivors (21 of the audit's constant / reported-size / arithmetic / offset groups, 6 mislabelled `capacity`
and `capacity-1` ones): 27 killed, 0 equivalent, 0 blocked. Slowest facade check with the new laws: 100 to 160 s

## 7. Round 3: big-type sizes, union fallthrough, capacity-wrapped writes

New laws of `write_start_and_sizes.py` (and `mc_ser`'s witness now sets every seeded field):

* `ms_sizesym` (HistoricalBatch, SyncCommittee, LightClientBootstrap, LightClientUpdate, BlobSidecar): the size pass of a container
  constructed from symbolic fixed fields and default variable fields equals the schema's least size. Nothing is encoded, so
  the 524288-byte and 24624-byte types cost milliseconds. Kills 524288 to 524287, 24624 to 24625 / 24623, 24820 to 24821.
* `ms_putk` (fixed-size containers with a checked writer): the words at the first and last byte of every field, written by
  `X_putk` into an output of depth K and of depth K+2, are equal. `Array.set` indexes modulo the array length, so a write
  at `pos - 2048` lands on the same word as `pos + 2048` when the capacity is 4096 bytes: the single-capacity
  serialize / encode comparison cannot see MatrixEntry's `b48_put(out, pos + 2048)` to `pos - 2048`; a second capacity can.
* `ms_arm<i>` (unions): decode of the encoding of arm i (seeded payload) returns the arm. `ms_armbad`: a buffer whose selector
  names no arm (bit 7 set) reads as arm 0 through `X_read`: this pins the fallthrough `case False{}` of the last `rd` helper
  (`off + 1` to `off + 2`, `off + 1` to `off - 1`), which `X_decode` never reaches (`ok` refuses the selector).

Re-run (8 mutants): 7 killed with a statement mismatch at the new law; 1 equivalent: `CompatibleUnionA_rd0`, `len - 1` to `len - 0`
in the fallthrough branch: the callee chain `ProgressiveSingleFieldContainerTestStruct_read(buf, off, len)` passes `len` to `rd0`,
which never reads it, so the changed literal disappears under conversion (the argument is unused).
