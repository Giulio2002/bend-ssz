# Slop layout

The laws that exist because mutation testing found a gap in what the locked statements pin are called slop (as in AI slop: written by
generators, not by hand) and are kept apart from the rest of the
proofs: generators in `codegen/proofs/slop/`, generated modules in `proofs/slop/<group>/<name>_generated.bend`, their gate modules in `proofs/gate/slop/<group>/<name>_generated.bend`, documents in
`docs/mutation_testing/`. This note records what moved, how the wiring that reads those modules works now, and what changed in the
generated tree. (Before the move: 14 generators in `codegen/proofs/laws/` writing 1,431 modules into `proofs/obj/` under prefixes such as
`zcapsym_`, `wordpos_`, `mutval_`.)

## 3. Wiring

* **object_api_coverage_gate** (`codegen/proofs/facades/object_api_coverage_gate.py`). A proving file has a key: a bare name for `proofs/obj/<name>.bend`, and
  `slop/<group>/<name>_generated.bend` (a path below `proofs/`) for the new place. `proving_files()` lists `proofs/obj` (sorted) and then
  `proofs/slop` group by group in the order of `LAYOUT.GROUPS`, each sorted. **This is the explicit replacement of the z-prefix
  sort order**: the bridges and the facades read the first law of a kind, and the first proving import of an encode facade (P0, read by
  block_and_light_client_bridges / test_struct_and_union_bridges) must stay the name's own spec/encx file, so the slop laws come after every other proving file. The
  `late` list (the `<X>_mc_*` / `<X>_ms_*` laws of `constants/` and `size/`, which are appended after every other law) is unchanged; its
  recognition is by directory instead of by the `mutconst_` / `mutsmall_` prefix. The attribution of a law to a name still reads the name from the file
  stem (`ok_eval`: `_<X>_` in the stem; `constants/<X>`, `size/<X>`), which the new names keep. Gate modules: `proofs/gate/slop/<group>/<name>_generated.bend` for a slop module (`proofs/gate/slop/capacity/BLSPubkey_symbolic_generated.bend`; the
  group folders mirror `proofs/slop`, so two groups never collide), `proofs/gate/g__<name>_generated.bend` for a `proofs/obj` file. Proving files of a group are
  ordered by their names without the suffix (`LAYOUT.stem_of`), so the order of the laws does not depend on `_generated`.
* **Import paths.** Bend resolves `import` relative to the file. A slop module is one directory deeper than `proofs/obj`, so a
  generator writes its text as if it lived in `proofs/obj` and `slop_layout.placed()` re-bases it: `../x` gains one `../`, `./x` becomes
  `../../obj/x` unless `x` is written beside it (the library of the group). `object_api_coverage_gate.proving_imports` / `prv_import` give the imports of a
  proving file as seen from `proofs/api` and `proofs/gate` (the same depth), for gate modules and facades alike.
* **Readers of api_map.json** that open a proving file take the key through `object_api_coverage_gate.proof_path` (object_api_model_bridges, fixed_size_name_bridges); the others only see
  proofs/obj files as the first law of the kinds they read.
* **Facades** (`proofs/api/*_proof_generated.bend`): 573 of 720 change. 364 differ only in import lines (the paths of the moved modules); 209
  also list the same statements in the new order (306 (name, law kind) lists are reordered, no list gains or loses a law; for 173
  `serialize_valid` lists the first law is now the name's own `serialize_valid` law instead of a mutation law). `api_map.json` and
  `proofs/api/manifest.json` follow. `e2e/`, `types/` and every other file under `proofs/` are byte-identical.
* **Registry and tests.** `test_registry` (every `--check` script is registered, `MOVES.tsv` lists every registered generator's path),
  `test_imports` and `test_headers` pass unchanged; unit tests 36 of 36.

## 4. The auditor's harness

`tests_generated/mutation_testing.py --lib spec` checks a mutated spec file with the file itself and its two smallest direct importers. The
spec pins were found that way only because they are small. `lib_wide` now adds **every module of `proofs/slop/spec/` that
imports the mutated file**, whatever its size: the pins need not stay small, and the generators can add more (`spec_constants.py`,
`spec_constants_extra.py`: one entry per spec file, the output name is the spec file's name). `tests_generated/mutation_equivalence.py`
(`le_eq` equivalence) reads `proofs/slop/alignment/writer_guard_library_generated.bend` and requires the facade to import it.

## 5. frozen.lock.json

No change. `frozen.lock.json` hashes 42 whole files (none of them a moved module or a facade) and the statements of the `e2e/` statement
files with the definitions they reach; no moved module is in that reach. `tools/verify_frozen.py` without `--update`: *36 planted changes ok;
42 files, 4 statement roots, 1915 statement_defs files match*, on the regenerated tree.

## 6. Trial and checks (server, private tree)

* One regeneration (`regenerate_all -j 2`, nice 19) converged in one pass; `regenerate_all --check -j 2`: 131/131 generators up to date.
* Each moved module differs from its old text only in the header line, the import lines and `docs/` / `codegen/` paths in comments
  (11,544 import lines, 2,862 header lines, about 1,400 comment lines (one per module and generator) over 1,431 modules).
* Checked with `tools/check.sh` after the move: `spec/bytes.bend` (pin), `alignment/BLSPubkey_writer_guard.bend`,
  `offsets/BLSPubkey_word_positions.bend`, and the facades FuluBLSPubkey_encode_ssz, FuluAttestationData_encode_ssz, FuluCell_encode_ssz,
  FuluDeposit_decode_ssz, FuluBlob_hashtreeroot: all `ALL PROOFS CHECK`. `tools/umbrellas.py`: 9,156 files, 125 umbrellas, the same as before the move.
* Not run: the full check (gated separately).

## 7. Risks

* The facade statement order changed for 209 facades; the statements are the same, the P<i> aliases are renumbered. Anything that names
  `P<i>_` of a mutation module by position would notice (block_and_light_client_bridges / test_struct_and_union_bridges read only P0, which is unchanged).
* Gate module names changed (2,257 files: 1,419 moved to `proofs/gate/slop/`, 838 gained `_generated`): a script that imports `proofs/gate/g__<old stem>.bend` by name breaks.
* Fixer rounds that add pins write into `proofs/slop/spec/` through `spec_constants_extra.py` (one dict entry per spec file).
* A new slop generator must be given a group in `LAYOUT.GROUPS` and call `LAYOUT.finish(out, <its stem>, (<groups>), ...)`.

## 8. The rename to slop and the `_generated` suffix

Done in one regeneration on top of the layout above (naming rule: every generated file carries `_generated` in its file name).

* `proofs/mutation_coverage/` is now `proofs/slop/`, `codegen/proofs/mutation_coverage/` is `codegen/proofs/slop/` (generator stems unchanged),
  `codegen/core/mutation_layout.py` is `codegen/core/slop_layout.py` (`SLOP`, `SUFFIX`, `stem_of`), this note was `MUTATION_COVERAGE_LAYOUT.md`.
  `docs/mutation_testing/`, `tools/mutation_testing/` and the harness stay: they describe and run the testing, they are not slop.
* All 1,432 modules under `proofs/slop/` are `<name>_generated.bend`, including the group libraries (`writer_guard_library_generated.bend`,
  `aligned_path_library_generated.bend`); `slop_layout.rebase` writes the `./` imports of those libraries with the new names.
* Gate modules: 1,419 `g__mutation_coverage__<group>__<name>.bend` are now `proofs/gate/slop/<group>/<name>_generated.bend`; the other 838
  `g__<name>.bend` are `g__<name>_generated.bend`. No name collides (the group folders keep the groups apart; the gate stems of the flat modules are unchanged).
* Paths only: the facades (573) change in import lines, `proofs/api/manifest.json` and `proofs/gate/api_map.json` change in the `file` paths
  (`mutation_coverage/<group>/<name>.bend` is `slop/<group>/<name>_generated.bend`); every other line of every moved module is unchanged (normalized
  comparison with the tree before: only import lines and comment lines differ).
* `frozen.lock.json` is unchanged and `verify_frozen` (no `--update`) passes: no renamed file is hashed. `tools/check_costs.tsv`: the 838 gate rows follow their new names.
