# Runtime split per name and operation

Status: the additive stage is generated (codegen/runtime_refs.py, called by generate.py): the split files
below exist next to the monoliths and nothing imports them yet. The rest of this note is the plan. `types/fulu_obj.bend` (29k lines, 7.4k defs),
`types/generic_obj.bend` (24k lines) and every proof importing them stay as they are until this flips,
off main, once the facade (`codegen/api_facade.py`, `proofs/api/`) covers every name.

## Goal

For every readable name X (`codegen/names.py`: the 109 Fulu names; the generic forms under their
official class or structural names) the runtime is four generated modules:

| file | contents |
|---|---|
| `types/X_def_generated.bend` | the type (`type X is Type/Data`), its records' word types, `X_default`, field access, update, list append, `X_selector` / `X_force` |
| `types/X_encode_ssz_generated.bend` | `X_size`, `X_valid`, `X_put*` / `X_putv` / `X_putn` / `X_putk` / `X_pk`, `X_encode`, `X_serialize` (+ `_enc_*`, `_senc_*` helpers) |
| `types/X_decode_ssz_generated.bend` | `X_ok*`, `X_read*` / `X_rd*`, `X_decode`, `X_build` (+ `_some`, `_built`) |
| `types/X_hashtreeroot_generated.bend` | `X_root*`, `X_rt*`, `X_fin`, `X_hash_tree_root` |

The proof facade already has this shape: `proofs/api/X_{encode_ssz,decode_ssz,hashtreeroot}_proof_generated.bend`.

## What generate.py changes

`emit_all` today writes one stream: records, then `emit_shape(s)` for every shape in dependency order
(`g.order`), then `emit_api` per name, then the validity TAIL. The emitters already work per shape and,
inside a shape, per operation (`emit_ok`, `emit_valid`, `emit_putk`, the `_rd` / `_pw` / `_sz` / `_rt`
families). The split keeps every emitted definition byte-identical and only changes where it goes:

1. **An owner for every definition.** Each emitted `def`/`type` gets `(owner shape, operation)`. The
   owner is the shape the emitter was called for; the operation comes from the emitter (a table by
   emitter function, with the per-helper suffix families as the fallback: `_ok*`/`_rd*`/`_read`/
   `_decode`/`_build` → decode, `_sz*`/`_size`/`_va*`/`_valid`/`_pw*`/`_put*`/`_pk`/`_encode`/
   `_serialize` → encode, `_rt*`/`_root`/`_fin`/`_hash_tree_root` → hashtreeroot, the rest → def).
   `emit_all` collects `(owner, op) → lines` instead of one list. `--check` fails on a def with no owner.
2. **Shapes with no name.** Many shapes are not API names (field / element shapes: `l16_Withdrawal`,
   `b32`, `bits131072`, `v33_b32`, the wide groups `C_g0`, the boxed `X_bx`). Each gets the structural
   name `names.py` gives its form (`list_Withdrawal_16`, `vec_uint8_32`, `bitlist_131072`, ...) and its
   own four files; a group or box helper belongs to its container's files. names.py grows a
   `shape_name(shape)` for this, with the same no-collision check over names and shape names together.
3. **Imports.** A file imports `Base`, the `src/` modules it uses (as today: `B`, `D`, `M`, `O`), and
   for every other shape's symbol it references, that shape's file of the same operation, plus the
   def file of every shape whose type it mentions. The reference graph is computed from the emitted
   text (`\b(\w+)_(\w+)\(` against the owner table), not declared by hand; it is acyclic because
   `g.order` is already a dependency order (a shape's emitters only call earlier shapes'). Aliases:
   the shape's readable name with the operation's initial (`ComplexTestStruct_e`, `VarTestStruct_d`, ...);
   inside a file a symbol `T.foo(` becomes `<alias>.foo(`.
4. **Index files.** `types/fulu_obj_index.bend`, `fulu_obj_g*` / `fulu_obj_f*` (benchmark dispatch
   and fuzz groups) and their generic twins import the per-name files instead of the monoliths.
5. **A transitional monolith.** Until every consumer is rewired, generate.py keeps writing
   `types/fulu_obj.bend` / `generic_obj.bend` unchanged, so both layouts coexist and `--check`
   covers both. The monoliths are dropped in the last step.

## Rewiring the proof generators

About 900 modules in `proofs/obj` (325 import `fulu_obj.bend as T`, 288 `generic_obj.bend as T`) are
generated by some 60 generators; each writes `T.<symbol>` and a header `import ../../types/<mono> as T`.
Bend qualifies a name by its module alias, so one alias `T` cannot span several files. The rewiring is
one shared post-pass instead of edits to every generator:

- **`codegen/runtime_refs.py`** (new): loads the owner table from generate.py (the same computation,
  cached as `types/runtime_index.json`) and exposes `rewire(text) -> text`: every `T.<sym>` is replaced by
  `<alias(owner(sym), op(sym))>.<sym>`, the `import ../../types/<mono>.bend as T` line is replaced by the
  imports of exactly the files referenced (relative path kept from the original line), and names inside
  strings/comments are left alone. A symbol with no owner is an error.
- **Each generator** calls `runtime_refs.rewire` on each module text before writing (one line in each
  generator's output loop, next to its `--check` comparison). Generators that copy blocks from other
  modules (`var_vlist_enc.blocks`, `var_rec_enc` from `root_types.bend`) rewire after copying, so a copied
  block's references are rewritten too. Hand-written modules under `proofs/obj` (vcont, vrecx, vunion,
  ...) are rewired once by the same pass and committed.
- **`api_gate.py` / `api_facade.py`** read statements as written (after the rewire, `T.X_encode(` reads
  `X_e.X_encode(`): their API-symbol regexes (`T\.(\w+?)_(decode|encode|...)`) become alias-agnostic
  (`\b\w+\.(\w+?)_(decode|...)\(`), matched against the owner table.
- **The frozen spec side** (`spec/`, `schemas/`, `END_TO_END.bend`, `memory_bench/`) imports neither
  monolith (checked: `grep -l 'fulu_obj.bend\|generic_obj.bend'` finds only comments in `src/ssz.bend`
  and `src/obj.bend`), so no frozen file pins the monoliths. `memory_bench/law-statements.json` states laws
  by the object API's names (`T.X_encode`, ...); those texts are frozen, and the checker that compares
  them to the proofs must read the per-name alias as `T` (a normalisation in that comparison, not an edit
  of the statements).

## Order of work

1. names.py `shape_name` + the owner table + `runtime_index.json`; generate.py writes the per-name files
   next to the monoliths (both checked by `--check`); nothing imports them yet.
2. `runtime_refs.rewire`, applied first to `api_facade.py` (proofs/api only), checked there alone.
3. Generator by generator (smallest outputs first), rewire and re-check its outputs with checkq; each
   is a separate commit, the monolith still present, so any other worker's in-flight branch still merges.
4. Hand-written modules, then api_gate's regexes.
5. When no module imports a monolith, drop it.

Check cost: Bend re-checks every imported module, so a proof that today imports the 29k-line monolith
imports only its dependencies' four-per-shape files; the checker's per-module time should fall, most
for the small names. The per-name facade modules import several proving files each (several of them
big), so the facade's total check time is higher than the gate's (one module per proving file); the
gate stays the fast whole-API check, the facade the per-name view.
