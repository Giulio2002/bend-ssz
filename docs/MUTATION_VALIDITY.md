# Mutation testing, proof side: the validity-check group (round 1)

160 of the 606 surviving proof-side mutants of round 1 sit in a validity pass (`P_valid`, the `pk` poison flags, the
decoders' `ok` for vectors of booleans). All were killed by the runtime tests; the proofs did not notice because the
statements about the checked serializer all start from `P_valid(o) == True` (or `False`): none says when the pass is
one or the other. The laws below say it, from the schema, in the encode facade of each name
(`proofs/api/<X>_encode_ssz_proof_generated.bend`), where the mutation harness checks. They are generated by
`codegen/proofs/laws/mutation_laws_validity.py` into `proofs/obj/mutval_<runtime>_<X>.bend` (one file per name, 185 files,
221 laws; api_gate files them as `serialize_valid` laws through three law-name forms).

| Law | Names | What it pins |
|---|---|---|
| `X_serialize_vdom(o)`: `X_serialize(o) == X_ser_pick(DOM(o), o)` | every Data name: bool, uintN, Bytes1, byte vectors, bit vectors, fixed containers | `True{}` where the schema says every object is valid; `U32.is_le(o, 255)` / `65535` for uint8 / uint16; `U32.is_lt(w, 256)` for Bytes1; `U32.is_lt(w_last, 2^(k mod 32))` for a bit vector of k bits. DOM is derived from the schema, never from the generated check; the generator stops when they disagree. |
| `X_serialize_vin[_n]()` | words and bits names | the serializer of an object at the accepted edge (a vector's exact length; 0 and one element for a list; the limit for a bit list) is its encoding: kills a wrong lower bound, unit or bits-past-the-end rule, a forced `False{}`, a bool check |
| `X_serialize_vover()` | words and bits names with a finite limit | one past the limit is refused: kills a wrong upper bound or unbounded flag |

Objects in the edge laws carry a concrete zero storage (the check reads its size; a variable one would leave the result
stuck). That bounds what can be stated: edges up to 16500 bytes or bits (the largest vector but Blob is 16416 bytes;
the file of one such vector takes about a minute to check). Blob (131072 bytes) and a list limit of 2^30 (Transaction) are
beyond it; Blob keeps the older `_in`/`_over` of mutation_laws.py for the byte vector sizes up to 4096 and its `_over`.

## Result (160 mutants, one batch, pinned checker, `tools/check.sh` on the facade file)

* 119 killed. The batch ran twice: once after the first generation of the laws, then the 58 survivors again after the
  boolean vectors and the sizes up to 16500 bytes were added.
* 40 survive and are equivalent, by arithmetic (checked mechanically against the survivor list):
  * 14 `pk_ok` flag `0 -> 1`: the flag is read only as `is_poisoned(m) = 2147483648 <= m`; a low bit changes nothing.
  * 6 decode `v<N>_bool_ok_n` `is_eq(n, 0) -> is_lt(n, 0)` and `ok_nz` `True{} -> False{}`: `ok_n` is called with the literal
    vector length (at least 1), so the `n == 0` branch is never taken.
  * 15 upper bound `+1` where `n = hi + 1` is refused anyway: the unit check (the length must be a multiple of 2, 4, 8, 16, 32
    and `hi` is one) for the vectors of wider elements, and the unbounded flag (`big = True`) for the progressive lists
    (`pl_*_valid`, `0 -> 1` on the unused `hi`).
  * 4 unit `+1` that divides the only accepted length (`6 mod 3`, `20 mod 5`, `1026 mod 3`, an even 512 for unit 1 to 2).
  * 1 progressive bit list: `bits_ok(o, 0, True{})`, the limit is unused when unbounded.
* 1 not coverable (the 160th): `Transaction`, `bl1073741824_valid` upper bound `1073741824 -> 1073741825`: a counterexample needs an
  object of 2^30 + 1 bytes, that is 2^28 words of storage; no concrete term of that size can be checked. It is a bound on
  a constant, shared with the decoder's, that the end-to-end size laws already use at 2^30.
